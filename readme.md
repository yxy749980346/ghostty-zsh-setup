# Ghostty Zsh Setup

[中文说明](readme-zh.md)

This is a macOS setup script for Ghostty and Zsh. It installs common command-line tools, configures Ghostty themes, fonts, appearance, keybindings, and window layout, and provides an automatic progress indicator for Ghostty.

The script preserves the existing contents of `~/.zshrc` and only updates its own marked configuration block. It does not replace your existing environment variables, aliases, proxy settings, private variables, or other shell configuration.

## Features

- Install or check Homebrew, Oh My Zsh, and common command-line tools.
- Install Zsh plugins such as `zsh-autosuggestions` and `zsh-syntax-highlighting`.
- Install Meslo Nerd Font and the MesloLGS NF font used by the Ghostty configuration.
- Configure the Catppuccin Mocha Purple theme, translucent background, window padding, and window layout restoration.
- Configure a global `Option + Space` shortcut for opening a terminal window.
- Configure Starship, zoxide, yazi, lazygit, and common aliases.
- Show an automatic Ghostty progress indicator for long-running foreground commands.
- Validate the generated configuration with Ghostty's built-in validator.

The script does not install the Ghostty application itself. Install Ghostty from its official website or another trusted source before running the script.

## Prerequisites

- macOS.
- Run the script as a regular user. Do not run `sudo bash setup-ghostty-env.sh`.
- `zsh`, `git`, and `curl` available on the system.
- Network access to Homebrew, GitHub, codeload, raw, and jsDelivr.

If Xcode Command Line Tools are not installed, run:

```bash
xcode-select --install
```

If Homebrew is not installed, full mode will attempt to install it. The installation may ask for your password or confirmation for system permissions.

To use the global terminal shortcut, allow Ghostty under macOS Accessibility settings and make sure `Option + Space` is not already used by another application.

## Quick start

After downloading or cloning the project, run the following commands from the project directory:

```bash
# Check the script syntax
bash -n setup-ghostty-env.sh

# Run the full setup
bash setup-ghostty-env.sh
```

The script shows a plan and waits for confirmation by default. To skip the script's own confirmation prompt:

```bash
bash setup-ghostty-env.sh --yes
# or
bash setup-ghostty-env.sh -y
```

`--yes` only skips the script's confirmation prompt. It does not bypass Homebrew prompts, system permissions, or password prompts.

## Modes

The default mode performs the full setup, including Homebrew, fonts, command-line tools, Oh My Zsh, Zsh plugins, Starship, Zsh integration, and Ghostty configuration.

To configure Ghostty only, run:

```bash
bash setup-ghostty-env.sh --ghostty-only
```

`--ghostty-only` installs the MesloLGS NF font used by the Ghostty configuration, writes the theme and Ghostty configuration, and validates the result. It does not:

- Install Homebrew, Oh My Zsh, Zsh plugins, or command-line tools.
- Modify `~/.zshrc`.
- Create or overwrite `~/.config/starship.toml`.

The legacy `--with-personal` option is still accepted for compatibility with older versions and is equivalent to the default full mode.

## Configuration file handling

| Path | Handling |
| --- | --- |
| `~/.zshrc` | Create a backup, remove and regenerate only the script's managed block, and preserve everything else |
| `~/.config/starship.toml` | Create a backup and regenerate the Catppuccin Powerline preset |
| `~/.config/ghostty/config` | Create a backup and regenerate the Ghostty configuration |
| `~/.config/ghostty/themes/Catppuccin Mocha Purple` | Create it if missing and preserve it if it already exists |
| `~/.oh-my-zsh` and plugin directories | Install them if missing and skip existing directories |
| `~/Library/Fonts` | Used to install fonts |

The block managed by the script in `.zshrc` is marked as follows:

```zsh
# >>> ghostty-zsh-setup managed >>>
# Ghostty and Zsh integration generated by the script
# <<< ghostty-zsh-setup managed <<<
```

On subsequent runs, the script only updates the content between these markers. Configuration outside the markers is preserved. The script also checks for existing functions and aliases with the same names to reduce the chance of overriding user-defined commands.

If you already have custom Starship or Ghostty configuration, save it separately before running the script. A timestamped backup is created first, and then the script regenerates the configuration.

## Applying the configuration

Ghostty usually hot-reloads its configuration after it is saved. You can also reload it in Ghostty with `Cmd + Shift + ,`.

After the Zsh integration is written, run the following in the current terminal:

```zsh
exec zsh
```

You can also close the current window and open Ghostty again.

After installation, you can test the setup with:

```zsh
z partial-project-name    # Smart directory jumping with zoxide
y                         # File manager with yazi
lg                        # lazygit
ll                        # ls -lah
sleep 3                   # Observe the automatic progress indicator
```

Starship and the automatic progress indicator are enabled only when `TERM_PROGRAM=ghostty`. Other terminals will still load Oh My Zsh and the rest of their Zsh configuration.

## Automatic progress indicator

The automatic progress indicator shows that a command is still running; it does not represent the actual completion percentage. It normally starts after a command has run for about 1.5 seconds, so short commands do not show the blue indicator. The script suppresses the indicator when it detects a TUI or a terminal state that is not suitable for probing.

If a program manages its own progress through OSC 9;4, disable the script's automatic progress indicator for that command:

```zsh
GHOSTTY_PROGRESS_AUTO=0 your-command
```

You can also temporarily disable it in the current shell:

```zsh
export GHOSTTY_PROGRESS_AUTO=0

# Restore the default behavior
unset GHOSTTY_PROGRESS_AUTO
```

Runtime state for the automatic progress indicator is stored in `/tmp/.ghostty-progress-<UID>/`. Do not manually delete state files while the related terminal or worker is still running.

## Backups and recovery

Before overwriting an existing configuration, the script creates backups similar to:

```text
~/.zshrc.bak.YYYYMMDD-HHMMSS
~/.config/starship.toml.bak.YYYYMMDD-HHMMSS
~/.config/ghostty/config.bak.YYYYMMDD-HHMMSS
```

At the end of the run, the script lists the backup paths it created. To recover a configuration, first save the current file elsewhere, copy the desired backup back to its original path, then run `exec zsh` and reload the Ghostty configuration.

These backups apply only to configuration files. The script does not automatically uninstall Homebrew packages, fonts, Oh My Zsh, plugins, or themes that have already been created.

## Validation and troubleshooting

Check the script syntax:

```bash
bash -n setup-ghostty-env.sh
```

Validate the Ghostty configuration:

```bash
ghostty +validate-config --config-file="$HOME/.config/ghostty/config"
```

If Ghostty is installed in its default location but `ghostty` is not in `PATH`, run:

```bash
/Applications/Ghostty.app/Contents/MacOS/ghostty \
  +validate-config --config-file="$HOME/.config/ghostty/config"
```

Common issues:

- Font or icon problems: confirm that Ghostty uses `MesloLGS NF` or `MesloLGS Nerd Font`, then reopen Ghostty.
- The global shortcut does not work: check Accessibility permissions, shortcut conflicts, and the Ghostty configuration validation result.
- Configuration validation fails: adjust configuration options according to the installed Ghostty version. The script prints a warning but does not automatically roll back files that have already been written.
- Downloads fail: check your network connection and access to Homebrew, GitHub, jsDelivr, and related services.

The script uses current upstream content and does not pin every dependency version. Review the script and its download sources before using it in a production environment.
